# Slack connector 0.14.0

Optional saved-connection enrollment adds Connect/Disconnect through the owning
Instance Connections page. The domain closes admission, drains current work,
acknowledges context handoffs and observes the actual socket state. Credentials
and conversation bindings are retained. Lost acknowledgments reconcile the same
operation through status; no model prompt or message is sent by verification.

An optional installation-owned typed Add provider creates a separate paused
connector in an owner-approved slot, using the existing installer. Settings
completes Slack account approval; Connect then activates the saved connection.
No arbitrary browser host commands, paths or credentials are accepted. Existing
standalone installations keep their current controls until explicitly enrolled.

Requires compatible Instance saved-connections support for the shared UI; the
underlying ACP engine and standard standalone connector remain independent.
See [saved connections](../saved-connections.md) for installation prerequisites,
fixed command registration, no-overwrite and status-only recovery semantics.
Publication alone does not enroll installations or grant task authority.
