# Slack connector 0.15.0

Accepted background work can schedule a durable result check through the existing
conversation MCP server. Quiet checks no longer require a public progress message
or wait for its delivery. The plain-ACP follow-up footer uses the same scheduler;
a newer human question carries the unfinished check in the existing work handoff.
No new task record, model classifier or shared service is required.

Known ACP turn limits can continue the same work after terminal tool results,
without publishing partial text or repeating the original request. Cancellation,
refusal and uncertain operations do not trigger an automatic retry. The existing
source, audience, endpoint and continuation bounds remain enforced.

With Instance's negotiated no-forward attention evidence, the status message now
says the input was not forwarded. Unmarked or mismatched errors remain uncertain.
Provider error text is never copied into the public status message.

Validation includes real connector, Slack loopback, ACP and MCP subprocesses:
background failure after a quiet response and restart, one-effect continuation
after a turn limit, exact no-forward rejection, and unchanged uncertain handling.
These are disposable protocol/behavior fixtures, not a claim that a live model
will always remember to schedule its unfinished work.
