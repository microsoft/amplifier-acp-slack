# 0.10.2 — Smaller active updates and no recovery-notice feedback loops

New messages and reactions during a running turn now send an incremental source
update. They preserve the message ID, revision, author, reply location, and the
original requester for peer awareness. The connector no longer repeats its full
history, parent/thread orientation, and delivery receipts on every update.
Attention judgment still receives local conversation evidence; additional context
remains available through the same scoped tools. Incremental messages do not
replace the initial context snapshot or each other.

Connector-generated recovery notices are persisted and published as controls.
Peer adapters exclude them from work intake and awareness, including edits and
deletes. A detailed notice retires the temporary work indicator once sent, avoiding
two error messages for one failure. The notice's own delivery echo still confirms
publication. Explicit reads of a thread rooted in an error keep that root visible.

Regressions cover failure notices circulating between agents, duplicate status
presentation, metadata-free own echoes, preserved thread roots, and small ordered
updates with unchanged source revision and authority. These changes do not retry
uncertain work or resolve a runtime's unknown input receipts.
