# Slack Connector 0.18.2

Local management requests wait for the verified HTTP connection to be ready
before sending the installation proof and authenticated operation. Previously,
a healthy native connector could reject setup's configuration request with
“connection was not ready” after the proof response. This could leave guided
setup reporting an uncertain outcome even though the connector had started.

The credential remains on the same proved connection. A closed connection or
uncertain operation is not reconnected or retried, and existing authentication,
request time limits, settings and credentials are unchanged.

The speech fixture now waits for startup within its decision's existing execution
budget before checking the unchanged eight-second speech-delivery requirement.
This changes test sequencing, not the connector's execution budget.

Release qualification covers disposable fixtures and native packages. It does
not establish live Slack workspace approval, first-message delivery or personal
desktop acceptance; those remain separate checks.
