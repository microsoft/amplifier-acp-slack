# 0.17.6

Each Slack connection can name its intended workspace before authorization.
Setup shows that intention separately from Slack's approval, refuses a mismatch,
and asks for confirmation when no workspace was declared. If app deployment may
have started, a lost reply does not discard the saved access needed to reconcile
it. Existing connected installations keep their credentials and sessions.

The connected page explains channel invitations. API errors retain the HTTP
status when no JSON response arrives, terminal job status and its explanation
are written together, and image synchronization waits briefly for its existing
lock before reporting it busy.

Newly installed Linux source services restart after outside termination.
Intentional service-manager stops and paused connections retain their existing
meaning. Existing units need the [documented policy change](../installation.md#staying-up);
an executable update alone does not apply it. The updater still refuses units
with drop-in overrides.

Workspace binding and channel guidance have disposable fixture coverage, not a
new live Slack authorization claim. The workspace-ID-only Slackbot link remains
unverified against Slack; the workspace link and manual instructions are kept.
Downloads remain unsigned previews. Native update and recovery preserve saved
credentials and conversation data; they do not update the agent's engine.
