# 0.16.0

Accepted Slack work can continue until it is finished, stopped or blocked. New
follow-up chains no longer stop after eight turns or 24 hours. Existing saved
chains retain their original finite limits, counters and cancellation state;
upgrading does not revive or extend them.

Already-admitted peer work can use the same durable follow-up tool or plain-ACP
footer as human-origin work. Each check keeps its original source, conversation,
endpoint and permissions. Slack membership and the exact source are rechecked
before another prompt. Nearby peer messages cannot replace the source of a queued
check. Configured model capacity, public reply policy, Stop and unresolved-effect
handling remain unchanged. No additional scheduler or work ledger is introduced.

Tests cover a ten-turn chain, legacy database migration and limits, human/peer MCP
receipt scope, source isolation, and actual connector/ACP/MCP continuation after
restart. Deleted sources stop before another prompt; lost scheduling receipts do
not move or duplicate the check. Fixtures use disposable homes and loopback Slack
and ACP services, not production conversations or a live model.
