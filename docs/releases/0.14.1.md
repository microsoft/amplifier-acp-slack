# Slack connector 0.14.1

Saved Connect/Disconnect now uses an existing host-owned admission lock without
changing its directory permissions. This allows connection controls inside a
container where updater controls are intentionally mounted read-only. The same
lock inode still excludes concurrent update admission.

A request interrupted before its gate was written can continue through status
with its original operation ID after the fix. No request replay, permission
relaxation, credential replacement or conversation reset is needed.
