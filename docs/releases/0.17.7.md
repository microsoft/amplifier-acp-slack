# 0.17.7

Approval cards can now show **Always allow** and **Always reject** alongside
single-request choices when the connected agent offers those options. Slack
returns the exact selected choice to the original request. The agent decides
which future requests match a remembered rule and provides its review and
revocation controls; the connector does not create its own approval rules.

Cards retain the original action details after a decision and explain when a
remembered choice was selected. The requesting person, workspace, app, message,
session and live request must still match. Expired or cancelled requests cannot
be revived by a later click.

The existing **Ask before actions** setting is unchanged. When disabled, it
automatically chooses an advertised single-request allow option, never an
Always option. No installation setting changes as part of this update.

Agents must send their approval requests through ACP for the Slack controls to
appear. Updating this connector alone does not expose an agent's internal web
approval or add remembered-policy support to that agent. Existing execution and
human-decision budgets are unchanged. Native downloads remain unsigned.
