# Slack Connector 0.18.0

Observatory can prepare and connect a self-contained Slack installation from its
setup screens. The connector supplies its own setup runtime and Slack tooling;
people do not need a terminal, system Python or a developer toolchain. Workspace
authorization and any administrator approval still take place through Slack.
The intended workspace and the approved workspace remain separate until checked.

New Windows and macOS installations started through Observatory run independently
of its window. Closing or reopening Observatory preserves the saved connection.
Starting a stopped saved connection is an explicit action and keeps its existing
configuration. These installations do not automatically start at sign-in.

Authorization can be reopened without issuing another request. Known rejected or
expired confirmations are distinguished from an unconfirmed outcome; an uncertain
request is not repeated. Temporary authorization commands are not saved in
Observatory's setup record. Existing credentials, conversations, remembered
approval choices and connected agents are retained.

Managed installations use an independent, temporary native worker for updates and
Restore. The worker preserves settings and conversations. The update screen
requests cleanup of that worker's temporary registration after completion;
the connector checks its exact ownership and inactivity before retirement.
Unconfirmed stop, update or cleanup
outcomes remain visible rather than causing another dispatch or broad cleanup.
Existing manually launched and Linux installation paths keep their separate
lifecycle behavior.

This release also includes the accepted conversation projection change: compatible
Instances receive Slack context once, and a completed quiet ambient turn need not
create an unnecessary reply. Grant checks, message delivery, and uncertainty rules
remain in force; incompatible peers retain the existing context path.

The native preview is unsigned and not notarized. Normal operating-system
security prompts and workspace policy still apply. Local account and lifecycle
fixtures do not constitute a live workspace authorization or model-response test.
