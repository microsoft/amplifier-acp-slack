# 0.17.3

Follow-up Slack turns now resume the saved conversation when an ACP endpoint advertises session resume without session loading. A failed resume preserves the existing session binding and reports the failure before sending a prompt or creating a replacement conversation.

Endpoints that support session loading retain the existing preference and recovery behavior. Permission modes, client callbacks, source scope and delivery ownership remain unchanged. The connector negotiates the capability with any compatible ACP endpoint.

This patch keeps the same dependency selections and native installation/update behavior. Existing credentials and conversation state remain with the installation. Downloads remain unsigned previews.
