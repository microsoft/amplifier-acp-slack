# Slack connector 0.17.12

Agents now receive Slack's workspace message and thread links, making it easier
to point you back to the discussion or delivered reply. Connections that have
not learned the workspace address retain the existing web-client links.

In a conversation with people, an agent can send its configured owner a private
message with a link back to the source. The owner must belong to that source
conversation, direct messages must be enabled, and any configured conversation
allowlist must permit the owner's DM. The tool cannot choose another recipient
and is limited to three messages per response. It is unavailable in DMs and
responses to other agents. Older Slack installations need the existing
`im:write` permission to open a DM.

Queued private messages recheck their saved recipient, destination and source,
and confirm source access with Slack before each send, including rate-limit
retries. Lost access cancels the private message. If Slack cannot confirm access,
delivery waits briefly and cancels after two minutes from the first claim rather
than indefinitely holding up the response. Uncertain sends are reconciled by
their original identity, never repeated.

PDFs that cannot be passed whole can now be read as text: up to 32 MiB of PDF
input and 200 KB of extracted text. The result identifies page coverage and
omissions; figures, scanned pages and layout are not extracted. Password-protected,
damaged or unreadable files produce an explanation. Parsing runs in a bounded
child process; platform-specific limits are described in [media](../media.md).
Small supported PDFs continue to be passed whole.

This release includes PRs #80, #81 and #82. Approval preferences, remembered rules,
credentials and saved conversations are unchanged. No engine or Instance update
is required. The new private-message and PDF behavior is covered by disposable
fixtures and the six-platform package checks; this is not a claim of a new live
workspace or model trial.
