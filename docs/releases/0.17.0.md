# 0.17.0

Agents can create or reuse a Slack discussion thread for routine coordination,
then return meaningful progress, decisions and results to the original channel
or thread. People can inspect and join with Slack's existing controls. Routine
replies stay in the side thread without channel broadcasts; Slack still owns
personal notification preferences.

The connector reuses its existing MCP connection, independent conversation
sessions and durable message publisher. Saved source bindings fix the return
destination. Lost acknowledgements retain the original send identity for
reconciliation, and an accepted tool delivery does not force a redundant public
acknowledgement. Participation does not grant new work authority.

See [side conversations](../side-conversations.md) for interfaces, audience limits
and validation. These are ordinary discussion threads, not audio Huddles. Direct
messages and thread-restricted grants do not open wider channel conversations.
