# Slack Connector 0.18.1

Guided setup invokes its private Python hooks from the installation's fixed
project directory. Windows, macOS and native Linux home paths containing spaces,
repeated spaces or shell characters no longer become shell command text. The
helper checks the project layout and selected private interpreter before writing
the project. Existing Linux PAM installations keep their system-Python route;
unusual whitespace in that external interpreter path remains outside this fix.

The connector continues to provide its own runtime and pinned Slack setup tool.
People do not need Git, npm, Deno, system Python or an operating-system terminal.
Slack approval, confirmation of the intended workspace and any administrator
approval remain explicit. This change does not reuse or replace credentials,
repeat uncertain requests, increase time limits or grant new Slack permissions.

This release also carries the accepted named Slack attachment delivery and
owner-message tool eligibility changes. The owner-message tool is listed by the
conversation's eligibility, rather than by who spoke last; its existing source,
audience and dispatch checks remain in force.

At source preparation, exact native package qualification is still pending.
The package fixture exercises the generated commands with the platform shell,
private Python and fictional local credentials, without Slack authorization or
app deployment. Its Windows console observations are bounded and do not prove
universal absence of a brief window. A successful fixture is not a live Slack
workspace approval, model-response test or ordinary desktop acceptance.
